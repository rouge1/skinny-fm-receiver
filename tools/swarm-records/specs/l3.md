# Phase l3 spec: `tools/iq-lte`, from a recording to PCI, and with `--decode` to the cell's broadcast identity

Goal: `tools/iq-lte FILE` takes any recording the app reads, cuts out a 10 MHz-class block and prints the structural
fingerprint (verdict, PSS root, PCI, frame timing, bandwidth class) as JSON. With `--decode` it hands the same block to
srsRAN 4G's `pdsch_ue` (an outside program, never installed by this repo) to read the MIB and the SIB1 the cell
broadcasts, and prints the operator code, tracking area code, cell identity and band. Broadcast system information
only: the tool decodes the MIB and the SI-RNTI (0xFFFF) PDSCH and nothing else; it never looks at user data. Numpy only
in the repo; the outside tools are subprocesses, like `tools/iq-decode` and rtl_433.

Read `CLAUDE.md`, `AGENTS.md`, `tools/iq-decode` (the pattern: argparse, `iqmeasure.extract`, exit codes, outside
program, JSON), `tools/fm_receiver/iqlte.py` (`fingerprint`, `sss_search`), `tools/fm_receiver/iqmeasure.py`
(`extract`) and `tools/tests/test_iq_decode.py` (a test with a stub outside program).

Base: branch `lte-base2`. Every worktree is made `--from lte-base2`. The manager commits the Gates on `main` (the tool
reads `main:`), nothing else goes to `main`. Nothing is merged or pushed: branches are handed to the planner.

First command of the manager: `swarm.py phase l3 active`. Register every task WITH its model. Haiku is a Claude-driver
subagent with the Agent tool's model `haiku` (verified `claude-haiku-5-5` from transcripts); description starts
`[l3:<task>:haiku]`, then `swarm.py log-run`. Each Haiku subagent states its model id first in its report.

## What the outside setup is (the planner built it; workers never touch it)
`$FMRX_LTE_TOOLS` (default `/data/python/lte-tools`) holds: `run_pdsch.sh` (a wrapper: `run_pdsch.sh FILE PCI OFFSET
NSF PORTS`, prints pdsch_ue's lines; `PDSCH_DUMP=path` appends each decoded transport block to `path` as records
`0xA5, subframe, nbytes_lo, nbytes_hi, bytes`), the patched `pdsch_ue`, and a Python with pycrate at
`pyc/bin/python` (it decodes the 36.331 SIB1 from UPER bytes). `pdsch_ue` reads a cf32 file at 15.36 MS/s for a 10 MHz
carrier (`-Q -p 50`), does NOT search for timing (the file must start at a frame start: `-O OFFSET`), needs the cell ID,
and prints `Decoded MIB. SFN: n` plus a block with `PCI`, `Nof ports`, `PRB`, `Type`. Worker tests never run the real
programs: they use a stub directory (see Tests). Workers never read `/data/python/lte-tools` or `recordings/`.

## Behaviour (what the tests assert)
- `tools/iq-lte FILE [--block-center HZ] [--t0 S --t1 S] [--rate R --center HZ] [--decode] [--ports N ...]`.
  Stdout is one JSON document: `file`, `block_center_hz`, `rate_sps`, `duration_s`, `verdict`, `nid2`, `nid1`, `pci`,
  `nfft`, `bandwidth_mhz` (from `nfft`: 128 -> 1.4, 256 -> 3, 512 -> 5, 1024 -> 10, 1536 -> 15, 2048 -> 20),
  `half_frame`, `frame_offset_samples`, `checks` (as `fingerprint` returns them), and `decode` (null unless asked).
- Default `--block-center` is the file's centre. The block is moved to 0 Hz by mixing and read with `iqmeasure.extract`
  (band-limited, decimated; reading in chunks as the other tools do; at most 2**22 samples per read). Default span
  0.2 s from the start (`--t1` overrides; a longer span is allowed, up to 2 s).
- Exit 0 when the run completed, whatever the verdict. Exit 1 for a bad option or an unreadable file or a sweep file.
  Exit 2 when `--decode` is asked and the tools directory or a needed program is missing (message on stderr naming it).
- `--decode`: only when the verdict is `lte` and `pci` is not None (otherwise `decode` is
  `{"ran": false, "reason": "..."}`, exit 0). It resamples the block to 15.36 MS/s for a 10 MHz carrier (other
  bandwidths: the class's standard rate; the tool says in `decode.reason` when it does not support one, supporting
  only 10 MHz is acceptable this phase), writes it as a temporary cf32 file in a private temp directory (deleted after;
  never inside the repo or `recordings/`), and runs `$FMRX_LTE_TOOLS/run_pdsch.sh` with the PCI. The frame start is not
  known exactly (the SSS offset's meaning depends on the half-frame), so the tool tries these offsets in turn, mod the
  frame length (153600 samples at 15.36 MS/s): `o`, `o - 76800`, and ports 4, 2, 1, and stops at the first whose output
  contains `Decoded MIB`. `decode` then has: `mib` (`pci`, `ports`, `prb`, `type`, `cp`, `sfn`), `offset_samples`,
  `sib1` (the SIB1 fields below, or null with `sib1_reason`), and `tried` (the list of attempts).
- SIB1: the tool runs `PDSCH_DUMP` collecting the transport blocks, takes the most common 32-byte-or-longer payload
  from subframe 5, and parses it with `$FMRX_LTE_TOOLS/pyc/bin/python` (a helper run with that interpreter, written as
  a module `iqlte_decode.py` function that spawns `python -c` or a helper file under `tools/fm_receiver/`):
  `plmns` (list of `{mcc, mnc}` as digit strings), `tac` (int), `cell_identity` (int), `enb_id`, `cell_id`,
  `freq_band`, `cell_barred`, `q_rx_lev_min`. If pycrate is missing, `sib1` is null and `sib1_reason` says so; the
  `mib` still shows.
- Nothing else is read from the decoder: no DCI, no RNTI other than the broadcast one, no payload except the SIB1.
- Nothing is written into the repo or `recordings/`; temp files are removed.

## Tests (workers' own, synthetic)
- A synthetic 10 MHz LTE downlink (`lte_synth`, PCI 123) written as a `.cfile` plus `.sigmf-meta` at 20 MS/s, centre
  751.0 MHz with the block 300 kHz off the file's centre: `--block-center` correct gives `verdict lte`, `pci 123`,
  `bandwidth_mhz 10`; without it `verdict` is not `lte` or `pci` is None.
- Noise, `atsc_like` and `uplink_like` files: `verdict` not `lte`, `pci` None, exit 0. A missing file and a sweep
  `.sdvr`: exit 1. `--decode` with `FMRX_LTE_TOOLS` pointing at an empty directory: exit 2.
- A stub tools directory the test builds: a `run_pdsch.sh` script that, given an offset not equal to 0 and ports 4,
  prints the lines `Decoded MIB. SFN: 7`, ` - PCI:             123`, ` - Nof ports:       4`, ` - PRB:             50`,
  ` - Type:            FDD` and appends one dump record (a canned 32-byte payload, subframe 5) to `$PDSCH_DUMP`;
  otherwise prints `MIB not decoded`. With `--decode` the tool reports that attempt order and the first success
  (`tried` has at least one failed attempt before the success when the stub is made to need ports 4 after 2 or 1).
  The SIB1 parse is exercised only when `$FMRX_LTE_TOOLS/pyc/bin/python` imports pycrate; otherwise the test prints
  `SKIP sib1 parse (pycrate not available)`. The canned payload in the test is built by the test from a synthetic
  SIB1 with PLMN 001-01, TAC 0x1234, cell identity 0x0ABCD01, band 13 only when pycrate is available (the test
  must not contain bytes copied from any real cell).
- `--decode` leaves no temp file behind (the test lists the temp dir before and after).
