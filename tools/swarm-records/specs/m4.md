# Phase m4 spec: a pure tone is a carrier (two classifier bugs found on real files)

Goal: on real Sceptre files holding one CW tone (a VSG60 at -40 dBm; an IQ `.sdvr` at 28 MS/s, 40 dB SNR, and a
109 kS/s `.cdif`, 108 dB SNR) `iq-measure` says `carrier`. It said `fm` and `unknown`. Levels were right
(-39.83 dBm for -40.0 set). Read `CONTRACTS-measure.md` (its two new paragraphs: the tones rule and "Where the
envelope and frequency are measured"), `CLAUDE.md`, `AGENTS.md`.

First command of the manager: `swarm.py phase m4 active`. Register each task WITH its model
(`swarm.py task m4 <task> queued --model <m>`); never register one without `--model`.

## Behaviour (what the new tests assert)
- Band-limit before the envelope/frequency/burst/symbol-rate steps, as the contract paragraph says; the card's
  `occupied`, `level` and `tones` are unchanged except the tones rule.
- Tones: drop any tone more than 60 dB below the strongest.
- Synthetic cases (numpy; same helpers as the existing tests): (a) a CW tone at +50 kHz, 1 MS/s, 100 dB SNR:
  `class` carrier, exactly 1 tone; (b) the same at 28 MS/s over a 28 MHz band, 40 dB SNR (white noise): carrier,
  `frequency` spread under 500 Hz is not the point: the class must be `carrier`; (c) the m1 signal set (OOK, FSK,
  FM, AM, noise, two-tone) still classes as before: the whole existing 114-check suite passes unchanged.

## Gates (pre-registered)
- G1 `test_iq_measure.py` exits 0, with the new cases (a), (b) included and failing on the pre-fix code.
- G2 the other suites that import iqmeasure (`test_iq_tools.py`, `test_control_more.py`) exit 0.
- G3 the planner re-runs the two real files (not delegated): both `carrier`.
- G4 timing: 30 s of 1 MS/s IQ under 5 s and 1 GB (as m1's G4), measured by a probe.
- No bake-off: one author, two reviewers; any [high] finding is probe-verified before merge.
