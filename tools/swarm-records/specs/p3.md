# Phase 3 spec: spectrum recordings played without sound

Goal: a Sceptre sweep DVR (`.sdvr` of spectrum tiles) and a Sceptre spectrum `.fft` are listed in the Recordings
tab, and play: pick one, press Play, and the waterfall and trace run from the file on a timer, in dBm, with Loop
and seek, no sound and no radio.

Read `CONTRACTS.md` (the interfaces), `CLAUDE.md` (layout and rules) and `AGENTS.md` (worker rules) first.

## Behaviour (exact; this is what the tests assert)
- `spectra.open_spectra(path).read(...)` is as in `CONTRACTS.md`: dBm to the tile byte's own step (0.7 dB) for a
  DVR, exact for a `.fft`; rows by time; band by frequency; thinned by max; only the tiles a stretch touches are
  read; the file is never written; anything that is not a spectrum file raises `SpectraError`.
- `library` lists a sweep DVR and a `.fft` under the title **Sceptre spectrum**, one recording each, with the
  file's length from its sweeps, the time from its header (a bad one falls back to the file's mtime as for the
  IQ files), and no file name in the row text (it is in the tooltip). An IQ DVR is one IQ track; its own
  tiles are not a second recording.
- `library.render` draws a spectrum track as contracted: its own bins, in dBm, one sweep to a row, NaN outside.
- Playing a spectrum track opens no radio and no engine; the playhead is real time; Pause holds; seek works
  paused and playing; Loop off stops on the end, Loop on goes round; the level unit reads dBm; the waterfall
  runs; the audio box and everything else behave as for a recording with no sound.
- The IQ files (this app's own, `.sdvr` IQ, `.cdif`) play exactly as before: `test_sceptre_library.py`,
  `test_recordings.py`, `test_control.py`, `test_gui.py`, `test_dvr_iq.py`, `test_sceptre_dvr.py` still pass.

## Acceptance targets (numbers, measured by a script or test)
- `test_spectra.py` and `test_sceptre_spectra.py`: exit 0, "all checks passed".
- The six existing suites above: exit 0.
- Real file, measured by the planner after the merge, not by workers (a 1.03 GB sweep DVR: 54 tiles of 849
  sweeps, 1.2 million bins): listing it takes under 1.0 s warm and under 3 s cold; reading and rendering a
  30 s stretch at 8 rows by 2048 columns takes under 5 s. These bound the design: no whole-file read.

## Gates (pre-registered: fixed before any worker runs)
- G1 `tools/tests/test_spectra.py` exits 0 (denominator: its four checks).
- G2 `tools/tests/test_sceptre_spectra.py` exits 0 (two parts).
- G3 the six existing suites exit 0, run one by one from the merged worktree.
- G4 the planner's real-file timing, above, in the thresholds given.
- Bake-off scoring rubric (0 to 100): correctness against the spec and the tests, and bugs a reviewer finds that
  the tests miss, 50; spec compliance including the only-what-it-needs reading and no writes, 30; clarity and
  fit with the surrounding code, 20.
- Winner rule: the highest score; a tie goes to the entry with fewer failing review items, then the shorter diff.
  Read both diffs before choosing: hidden bugs can pass the tests.
- Controls: a deliberately wrong entry (rows read from the whole file) must fail `test_sdvr_reads_only_what_it_needs`;
  the planner's reference implementation passes `test_spectra.py`.

- Following a ring Sceptre is still writing (it lists what the file holds when scanned).
- The Sweep and Receive tabs, the radios, the engine, `sceptre_dvr.py` and `sceptre_blue.py` (read them, do not
  edit them; if one needs a change, say so in the final message).
- Writing, converting, deleting or moving any Sceptre file.
