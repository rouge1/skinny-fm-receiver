# Phase n2 spec: NR broadcast decode (`iq-nr --decode`: MIB, SIB1, other SI, SIB9 network time)

Goal: `tools/iq-nr FILE --decode` gives, for each NR cell `iqnr.ssb_search` found, the MIB, SIB1 (operator PLMNs,
tracking area, cell identity, barred or not, the SI schedule, the carrier), every other SIB the cell broadcasts, and
the network time from SIB9 when the cell sends it (or the reason there is none). Nothing of ours decodes: the block is
handed to an outside program (`$FMRX_LTE_TOOLS/run_nr.sh`, srsRAN 4G NR, AGPL, never in this repo), and the RRC
messages are parsed with pycrate in a subprocess (`$FMRX_LTE_TOOLS/pyc/bin/python`), exactly as `iqlte_decode.py`
does for LTE. Only the broadcast channel is read: the outside program searches the SI-RNTI (0xFFFF) and nothing else.
This repo never names, passes or searches any other RNTI.

Read `CLAUDE.md`, `AGENTS.md`, `knowledge/nr-verify.md`, `knowledge/lte-verify.md` (its decode and SI sections),
`tools/fm_receiver/iqnr.py`, `tools/iq-nr`, `tools/fm_receiver/iqlte_decode.py` (`_SI_HELPER`, `read_si`,
`summarise_si`, `sib16_time`, `nr_arfcn_mhz`, `SampleSource`, `_write_resampled`, `tools_dir`, `require_program`,
`ToolsMissing`), `tools/iq-lte` (`--decode`, `--si-seconds`, exit 2), `tools/tests/test_iq_lte.py` and
`tools/tests/test_iqlte_si.py` (how the stub tools folder and the pycrate encoder are built).

Base: branch `nr-decode-base` (the planner merges the n1 result `nr-ssb` and the SIB work `lte-sibs` into it before
this phase). Every worktree is made from `nr-decode-base`. The planner has committed this spec on `main`; nothing else
goes to `main`. Nothing is merged or pushed: the branches go to the planner.

## The outside program's contract (frozen; the stub in the tests prints exactly this)
`run_nr.sh FILE SRATE SSB_OFFSET_HZ SSB_ABS_HZ SCS_KHZ [-m MAX_MS] [-t SLIV,SLIV,...] [-a OFFSET_TO_POINT_A]`
- FILE: complex64 (cf32) samples at SRATE = 23040000 (a 106-PRB grid at 15 kHz), with the SSB centre mixed to 0 Hz,
  so SSB_OFFSET_HZ is 0. SSB_ABS_HZ: the SSB's absolute frequency (`ssb_hz` from `ssb_search`). SCS_KHZ: 15 or 30.
- `-m`: milliseconds to read (default the whole file). `-t`: SIB1's `pdsch-ConfigCommon` `pdsch-TimeDomainAllocationList`
  `startSymbolAndLength` values in list order (k0 0, type A assumed). `-a`: SIB1's
  `servingCellConfigCommon.downlinkConfigCommon.frequencyInfoDL.offsetToPointA`. Without `-a` only SIB1 decodes;
  the other SI messages need both `-t` and `-a`.
- Stdout, one JSON object per line after a tag; any other line is ignored:
  - `NR_MIB {"pci", "sfn", "ssb_index", "half_frame", "scs_common_khz", "ssb_subcarrier_offset",
    "dmrs_typeA_position", "coreset0_index", "search_space0_index", "cell_barred", "intra_freq_reselection",
    "ssb_sample", "cfo_hz", "snr_db"}` or `NR_NO_MIB {"tries", "reason"}`
  - `NR_CORESET0 {"offset_rb", "n_rb", "symbols", "grid_prb", "pointA_hz", "f0_hz"}` (diagnostic)
  - `NR_SI {"sfn", "slot", "sii", "vrb", "tbs", "hex"}`: one per SI-RNTI PDSCH whose CRC passed; `sii` 0 is SIB1,
    1 another SI message; `hex` the transport block (a BCCH-DL-SCH-Message, UPER, padded)
  - `NR_SI_CRC_FAIL {...}` and `NR_SI_ERR {...}`: diagnostic, counted only
  - `NR_DONE {"slots", "dci", "si", "crc_fail"}`, with `"reason"` when it stopped early (for example
    `k_SSB ... no CORESET 0, the cell sends no SIB1`)
- Exit 0 when it ran. On real air a 6 s file takes about 4 s.

## Method (`tools/fm_receiver/iqnr_decode.py`)
1. For each SSB entry: a `SampleSource` over [t0, t0 + seconds] of the recording, mixed so `ssb_hz` sits at 0 Hz,
   band-limited and resampled piecewise to 23.04 MS/s into a temp cf32 (reuse `iqlte_decode._write_resampled`; never
   hold the span whole: a 6 s 40 MS/s span is 1.9 GB as complex64).
2. Pass 1: `run_nr.sh FILE 23040000 0 ssb_hz scs`. Parse the lines. SIB1 is the most common `sii` 0 block.
3. Parse SIB1 with pycrate (`RRCNR.NR_RRC_Definitions.BCCH_DL_SCH_Message`, `from_uper`) in the pycrate
   subprocess (an `_NR_SI_HELPER` like `_SI_HELPER`: every distinct block in, plain JSON out).
4. If SIB1 schedules other SI (`si-SchedulingInfo.schedulingInfoList` not empty) and has `offsetToPointA` and a
   time allocation list (or none: then `-t` is left out), pass 2 with `-t` and `-a`. Collect every distinct block of
   both passes, parse, summarise.
5. Delete the temp folder in every case.

## Output (the `decode` key of each `ssbs` entry of `iq-nr --decode`)
`{"ran": true, "mib": {...NR_MIB fields}, "sib1": {...} | null, "si": {...} | null, "time": {...} | null,
"time_reason": str | null, "reason": str | null, "blocks": {"sib1": n, "other": n, "crc_fail": n}, "seconds": s}`, or
`{"ran": false, "reason": ...}`.
- `sib1`: `plmns` (list of "MCC-MNC" strings from every `plmn-IdentityInfoList` entry, MNC with its own digit count),
  `tac` (int or null), `cell_identity` (int, 36 bits), `cell_barred` (from the MIB), `si_window_slots`
  (`si-WindowLength` s5..s1280 as an int), `si_schedule` (list of `{"periodicity_rf", "broadcast_status", "sibs":
  ["sib2", ...]}`), `carrier` (`{"point_a_arfcn", "point_a_mhz" (via `nr_arfcn_mhz`), "bands", "carrier_prb",
  "scs_khz", "offset_to_point_a"}` or null).
- `si`: `{"sibs_heard": {"sib2": n, ...}, "sibs": {"sib2": {...plain}, ...}, "scheduled": [...], "missing": [...]}`
  (a scheduled SIB not heard in the span is `missing`, with the span length named in `time_reason` or `reason`).
- `time` (from SIB9 `timeInfo`): `utc` (ISO 8601 with milliseconds; `timeInfoUTC` is in 10 ms units from 1900-01-01
  00:00:00 UTC, as LTE SIB16), `gps` (UTC + `leapSeconds`), `leap_seconds`, `local_offset_minutes`
  (`localTimeOffset` x 15) and `dst_hours` when present; `reference_time` when `referenceTimeInfo-r16` is present:
  its raw fields plus `gps_reading` (GPS epoch 1980-01-06 + refDays days + refSeconds s + refMilliSeconds ms +
  refTenNanoSeconds x 10 ns, ISO 8601), described in the docstring as "the reading that agreed with timeInfoUTC on
  air; check against 38.331".
- `time_reason`: null when `time` is set; else one of "SIB1 does not schedule SIB9", "SIB9 scheduled but not heard
  in N s", "SIB9 is not broadcast (si-BroadcastStatus notBroadcasting: on demand)", "no SIB1", "no MIB". A missing
  time is a result, not a failure.

## Command
`tools/iq-nr FILE --decode [--decode-seconds S] [--max-cells N] [...]`: `--decode-seconds` default 6, at most 10 (cut
with a reason), validated like `iq-lte --si-seconds`; the SSB search still reads its own short span. Exit 2 (and a
message naming it) when `run_nr.sh` or the pycrate interpreter is missing under `$FMRX_LTE_TOOLS`, as `iq-lte` does.
Without `--decode`, output is byte-identical to before.

## Amendment 2026-10-23 (b), carrier point A (conservative: check C made stricter; found by the planner on real air)
- Bug: `sib1.carrier.point_a_*` came from pass 1's `NR_CORESET0 pointA_hz`, which is the outside program's stand-in
  grid (built from k_SSB alone), not the cell's point A. On real air it was 5.4 MHz off.
- Rule (FR1, 38.211 4.4.4.2 and 7.4.3.1; SIB1's FrequencyInfoDL-SIB has no point A ARFCN, only offsetToPointA):
  `point_a_hz = ssb_hz - 120 * ssb_scs_hz - k_SSB * 15e3 - offsetToPointA * 12 * 15e3`, where `ssb_hz` is the SSB
  centre, `ssb_scs_hz` the SSB's subcarrier spacing, and `k_SSB` the MIB's `ssb_subcarrier_offset`. `point_a_arfcn`
  is that frequency on the 5 kHz raster; `carrier` is null without offsetToPointA. `NR_CORESET0` stays diagnostic.
- Fixtures: SSB 600.15 MHz (15 kHz), k_SSB 0, offsetToPointA 10, so point A is 596.550 MHz, ARFCN 119310. Check C
  expects those instead of ARFCN 120000 / 600.000 MHz; one more case: k_SSB 6, offsetToPointA 13 at the same SSB
  gives 595.920 MHz (ARFCN 119184). Amendment (a) above no longer applies to point A.
