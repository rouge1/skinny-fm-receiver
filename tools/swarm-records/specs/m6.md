# Phase m6 spec: `tools/iq-decode`, the normalise-then-rtl_433 step

Goal: workflow step 7 as a tool: `iq-decode FILE` cuts the signal out of any IQ file the app reads, scales it to
where rtl_433's pulse detector can see it, runs rtl_433 on it and prints what it decoded as JSON. Over the air
(VSG60 -> antenna -> BB60D, 2026-10-14) a Nexus-TH frame was `ook` to `iq-measure` and decoded 11 of 11 packets
by rtl_433 only after the capture (-54 dBFS) was scaled up by 42 dB. Needs m5 merged (it edits the same file).
Read `CONTRACTS-measure.md` (the last section, "Decoding with rtl_433"), `CLAUDE.md`, `AGENTS.md`,
`tools/iq-measure` (the pattern).

First command of the manager: `swarm.py phase m6 active`. Register every task WITH its model
(`swarm.py task m6 <task> queued --model <m>`); never without `--model`.

## Behaviour (what the tests assert)
- The fixture frame (no import of the bench toolkit; the test builds it): Nexus-TH, one row of 36 bits
  `101101011000000010111110111101000111` (hex `b580bef47`: id 181, channel 1, 19.0 C, humidity 71), each bit a
  496 us mark then a gap of 1944 us for 1 and 964 us for 0; then a trailing 496 us mark; the row is repeated
  12 times with a 4000 us gap after each row's trailing mark (25000 us after the last); 5 ms of silence before
  the first; edges ramped over 16 us; amplitude 0.4 at 250 kS/s; complex noise of 0.003 per component.
- `iq-decode` of that frame written as a `.cfile` with a `.sigmf-meta` (250 kS/s, centre 433.92 MHz):
  `packets` >= 1, `summary` has `Nexus-TH` id 181, `decodes[0].temperature_C` is 19.0.
- The same frame scaled by 0.005 (-46 dB: the over-the-air level) and offset by 30 kHz in frequency: still
  decoded (`gain_db` reported, about +40), and the unscaled-file negative control: running rtl_433 directly on
  the scaled file decodes 0 (so the scaling is what is being tested).
- The same frame inside a 2 MS/s `.cfile` centred 200 kHz off, with `--band` around it: decoded.
- A noise-only file: `packets` 0, exit 0. A missing file or a sweep `.sdvr`: exit 1, message on stderr.
  `rtl_433` absent (the test points PATH away): exit 2.
- `extract` of that 2 MS/s file honours `max_rate`, returns the band centre as `center_hz`, and a counting
  source shows no read larger than 2**22 samples; more than 50 million output samples raises `IQSourceError`.
- rtl_433's stdout is read from a file, not a pipe.
- Investigate and write down in `iq-decode`'s docstring (one paragraph, measured, or "not reproduced"): why an
  over-the-air capture decoded with `-R 19` but not with the default set. The synthetic fixture cannot show it
  (it decodes either way): do not guess; say what was tried.
