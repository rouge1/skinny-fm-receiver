## Behaviour
- Every command of the contract's fmctl table is in `usage.md` with an example and in the skill's command list.
- `capabilities.md` has a status mark for each new capability: `built, tested on synthetic signals` (not
  `verified on air`); the real-file check is the planner's and is recorded by the planner after it.

## Gates (pre-registered)
- G0 (cdif-gain): a synthetic `.cdif` with `DATA_GAIN` 60 and a tone of raw amplitude 1000 (so |x|^2 is 1 mW
  after scaling) measures `power_dbm` 0.0 +/- 0.1, `power_dbfs` equal to it, `full_scale_dbm` 0.0; the same
  file without the keyword measures `power_dbm` None; `iq-picture` of the first file has its tone at 0 dBm
  +/- 1 dB in `peak_panel`'s data and labels the axis dBm. The planner re-runs the real FM `.cdif` after.
- G1 every new command and tool is named in `usage.md` and the skill (a grep the manager runs).
- G2 no file under `knowledge/` or the skill claims a decoder, `iq-demod` or `iq-frames` exists.
- G3 the full `tools/tests/run_all.py` exits 0 on the merged result.
