# Phase 0 spec: review the plan before building it

Goal: three workers review the measurement-tools plan (in `prompts/plan-r0.md`) from different lenses and a fourth
run reconciles them, so the planner can correct the plan and the later phases before any code is written.
Nothing is implemented or merged in this phase.

## Tasks and file ownership
| task | model(s) | edits only | notes |
|---|---|---|---|
| review-a completeness | grokw | nothing (read-only, `--kind review`) | `prompts/review-r0-a.md` |
| review-b control surface | musefree | nothing | `prompts/review-r0-b.md` |
| review-c architecture and reuse | haiku | nothing | `prompts/review-r0-c.md` |
| consensus | grokw (a model that did not write that review) | nothing | reads the three answers pasted into its prompt; every claim checked against the code |

Reviews run in detached worktrees of `main` (`wt r0 <name> --detach main`). Answers are saved with
`--text-out data/reviews/r0-<x>.md --kind review`. The manager pastes the three answers into the consensus
prompt (a worker may not read outside its worktree) and saves the consensus to `data/reviews/r0-consensus.md`.

## Behaviour
- Each review replies in the format its prompt gives (verdict, missing_tools, change_to_plan, risks).
- The consensus keeps a claim only if the code or the workflow text supports it, merges duplicates, and returns:
  `tools` (final list, with owner file, depends_on, parallel_group), `drop`, `reorder`, `fmctl_additions`
  (with the design decisions needing the user), `open_questions`.

## Acceptance targets
- Three review files and one consensus file exist and follow their formats.
- The consensus names, for each tool, an existing module to reuse or "none".

## Gates (pre-registered: fixed before any worker runs)
- G1 three review answers saved, each parsed to the verdict/missing_tools/change_to_plan/risks format
  (denominator: 3). A malformed answer is re-run once in its session, not edited.
- G2 the consensus file exists and has the sections above.
- G3 `git status` on main is clean after the phase (reviewers changed nothing) and no worktree has changes.
- No bake-off, no winner rule: reviews are merged, not ranked.

## Out of scope
- Writing code, tests or docs; merging; pushing; reading `/data/python/SDR` or any path outside the worktree.
